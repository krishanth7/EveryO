# EveryO v0.5.0 — Operational Engineering & Release Evidence

**Release type:** cumulative source and packaging checkpoint  
**Release date:** 2026-11-09  
**Python:** 3.9–3.12  
**Support scope:** CPU research services and qualification tooling

## Overview

This release records the cumulative CPU serving, monitoring, robustness,
artifact integrity, governance and release-assessment interfaces already
present on the main branch. As with v0.4.0, these APIs existed before the
v0.3.0 snapshot; v0.5.0 is a new distribution-version checkpoint and does not
claim they were introduced between these tags.

## Included capabilities

- Local authenticated inference serving, with bounded inputs and timeouts.
- Offline monitoring, drift checks, fault injection and CPU benchmark helpers.
- Archive validation, signed-artifact verification, and release-evidence gates.
- Documentation of production qualification, limitations, and deployment
  evidence still required in a real environment.

## Verification

```bash
python -m pip install -e ".[dev]"
python -m pytest -q
ruff check .
ruff format --check .
everyo doctor
```

## Security and production boundaries

**Not independently production-certified.** A passing CI matrix, artifact
signature tests, or a local service load run is not a substitute for
independent security assessment, an authenticated sustained soak test on the
deployment target, proven disaster recovery, key management, and operational
monitoring. See the
[`production qualification report`](../production-qualification-2026-11-09.md)
for evidence and gaps.

## Upgrade

The core source APIs match the v0.4.0 checkpoint except for version metadata
and documentation. When upgrading, rerun functional, numerical, security, and
load qualification in the actual target deployment environment.
