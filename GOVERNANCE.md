# EveryO Governance

EveryO is an independently maintained open-source project. This document explains how project decisions are made and how contributors can participate.

## Roles

### Maintainer

The maintainer sets the technical direction, manages releases, reviews changes, enforces project policies, and makes final decisions when consensus cannot be reached.

Current maintainer: [@krishanth7](https://github.com/krishanth7)

### Contributors

Anyone may contribute through issues, discussions, documentation, testing, code review, or pull requests. Contribution does not automatically grant commit, administrative, or release access.

### Reviewers and future maintainers

Consistent contributors may be invited to review or maintain specific areas. Access is based on demonstrated technical judgment, respectful collaboration, security awareness, and sustained participation. Access may be limited or removed when responsibilities change.

## Decision process

EveryO prefers transparent decisions:

1. Bugs and bounded improvements begin with an issue or pull request.
2. Architectural changes should begin with a GitHub Discussion or design issue.
3. Relevant trade-offs, compatibility effects, and alternatives should be recorded publicly.
4. The maintainer seeks practical consensus.
5. The maintainer makes the final decision when consensus is not possible.

Security reports follow [SECURITY.md](SECURITY.md) and must not be discussed publicly before coordinated disclosure.

## Releases

The maintainer approves release scope, version numbers, changelog content, and published artifacts. A feature appearing on the roadmap does not guarantee a release date.

## Changes to governance

Governance changes are proposed through pull requests and should explain their motivation. Material policy changes will be documented in the repository history.
